## Proposed visual contract

User-selected lime / black / soft white: soft-white page, white panels, black headings, lime current primary action with black text. Status/error/warning/success retain semantic text and an icon; do not rely on color for money, dispute or equipment status. Danger actions keep distinct danger treatment.

Space Grotesk headings **28sp / 34sp, 600**; Inter body **16sp / 24sp, 400**; labels **14–16sp, 600**; supporting **12–14sp, 400/500**. Verify font files, licenses and HI/TE glyph fallback before implementation; no renamed substitutes. Currency totals retain full readable numeric alignment.

One current-task heading and dominant action per state. Forms have persistent labels, inline errors, one scrollable content area and IME/inset-safe actions ≥48dp; major CTAs minimum52dp plus padding and grow with text. Large type turns cramped rows into wrapping/vertical arrangements. Preserve source route arguments, server gates and money/evidence truth.

No new booking guarantee, instant refund, automated offline submission or universal draft promise. “Offline” below means a failed-call presentation to design; a failed call alone is not proof of offline connectivity.

## Source constraints to resolve before implementation acceptance

1. **Booking truth:** MainNavGraph.kt:482–483 drops profile engineerId. RequestServiceViewModel.kt:853–870 creates RepairJobDraft without a target. Use Post a repair job and contextual header, until targeted booking is separately accepted.
2. **Bid chat mismatch:** RepairJobDetailScreen.kt:1781–1785 draws Message per bid, but RepairJobDetailViewModel.kt:574–587 searches only accepted bid, otherwise says no assigned engineer. Do not plan a working pre-accept bidder chat from that button alone.
3. **Unknown data:** AmcDetailScreen.kt:188–203 accepts failed section calls silently, null pool becomes0 at :404/:927. Portal disputes/reviews also swallow separate fetch failure. Per-section unknown/error requires future state work before UI can claim accurate values.
4. **Fallback location:** LocationPickerMap.kt:136–155 may emit Hyderabad after no fix/denial. Distinguish fallback/manual/located; keep typed address. No GPS/geofence success claim.
5. **Provider/payment truth:** existing marker stores must preserve paid-but-unverified. Renders do not prove Razorpay production readiness, mandate authorization, settlement/refund. Amount/dismissal changes need cancellation/late-result tests.
6. **Persistence:** RequestService has an account/session lease and durable recovery. AMC wizard saves subset in SavedStateHandle; DSR signature and Portal form use rememberSaveable; directory uses VM/local state. No universal everything-saved claim; owner boundaries need review before expansion.
7. **Affordance truth:** tab Back no-op; Filter Apply closes already-applied choices; call Cancel dismisses notice; Rated-done is disabled. Read-only AMC cards get no fake chevrons/actions.
8. **Authorization:** theme/tab/ID/isHospital arguments do not grant access. Preserve upstream/server checks and add foreign-account tests for later behavior changes. Shared Repair/AMC source ownership must be coordinated with engineer/auth owners.
