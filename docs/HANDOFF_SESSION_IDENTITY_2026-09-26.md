## Owned change

- `SessionViewModel` observes every auth event without suspending the collector on profile, token or preference I/O. Observed sign-out and account replacement advance a local login generation. The root state derives from a server profile for that generation, never a device-global cached role/onboarding value. A late cancelled/noncooperative result must match the latest request, observed generation and live auth identity before publishing or starting deletion effects. Unknown waits without minting a login; blank IDs stay gated; manual refresh does not queue for a future user. Token registration runs separately.
- Signed-out and profile mirror writes share a mutex and recheck ownership around suspension. An old noncooperative mirror clear may finish, but B's verified write must follow before B's root gate publishes. This does **not** make other global writers or the internals of `SignOutCleanup` owner-safe.
- An atomic `SessionPresentation` carries state, observed owner/generation, server-validated role and validation/resolution flags into the root. `RootSessionBoundary` hides pending/Unknown/revalidation content under an opaque pointer/Back-blocking cover, resets account-scoped hosts on A→B, A→out→A and confirmed role loss/change, and retains the same-login host during transient Unknown. Failed profile verification exposes a Retry control while keeping private content hidden. Main tabs/repair dispatch use the server-validated role rather than a stale role preference.
- Root, Auth and Onboarding hosts now share the same `SessionViewModel`, rather than fetching through separate destination-scoped instances. Root Main content admission checks the current owner/validated role synchronously; a demotion cannot briefly use the old cached-role fallback. A server role removal resets the old role NavHost. The fresh signup auth host is retained through hospital phone collection; server-validated role, not the signup effect, admits the phone route. Phone completion revalidates the root profile before Main/Onboarding handoff.
- `SignUpScreen.kt` first incorporates the helper's frozen accessible-footer blob `854f6bf781e01521cfd8558beec1c875640c6923` (its commit `ec423858`) and adds only the engineer `NavigateToHome` callback into the root recheck. The helper's own exact-source full run covered that footer, not this combined security tree. `AuthNavGraph.kt` now forwards hospital phone request/completion and engineer profile-commit callbacks. These combined edits need their own tests/review.
