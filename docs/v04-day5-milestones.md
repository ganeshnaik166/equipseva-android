## Three critical bug fixes

### r847-r849 — Broken founder RPC grants

13 founder RPCs (r481/r498/r499/r500/r505/r507/r508/r509/r510) were
granted `EXECUTE TO service_role` only. But the web ops console calls
them from the founder's SSR session (authenticated role). Result:
every load of `/unit-economics`, `/engineers/[id]`, `/health`,
`/risk`, `/supply`, `/ops`, `/hospitals/[id]`, `/funnel`,
`/disputes` (action) threw `permission denied for function ...`
and rendered Next.js's error boundary instead of the data.

Latent since 2026-08-17/18 (~3 months). Fix: add
`GRANT EXECUTE TO authenticated` for each.

Followed up with r852 `/grants-audit` page to surface the same pattern
proactively for future founder_* RPCs.

### r856 — engineer_payouts.amount_rupees missing

r422 created `engineer_payouts` with only `amount_paise bigint`. But
three later functions referenced `ep.amount_rupees`:

  - r489 `run_daily_reconciliation` (cron — three-way recon)
  - r490 `compute_tds_194o` trigger (per-payout TDS withholding)
  - r499 `founder_engineer_ltv_ranked`

If the column was actually missing in production (vs. added via
Supabase dashboard SQL outside migration history), then the recon
cron has been silently throwing since 2026-08-08 and the TDS
withholding trigger since 2026-08-09 — a compliance liability
because engineers received un-deducted payouts and the company would
owe TDS to govt for the gap.

Fix: defensively `ALTER TABLE … ADD COLUMN IF NOT EXISTS amount_rupees
numeric(12,2) GENERATED ALWAYS AS (round(amount_paise/100.0, 2))
STORED`. If column already existed via dashboard SQL, the IF NOT
EXISTS is a no-op (no behavior change). If missing, it now works.

Followed up with r857 `/reconciliation-health` and r858 `/tds-health`
diagnostic pages so the founder can verify post-deploy which case
applied.

## Anti-mod defense stack (14 layers, mostly r843-r856)

1. R8 minify + resource shrink (release)
2. Cert pinning (supabase.co + razorpay.com)
3. User-installed CAs rejected · cleartext blocked
4. Signature SHA-256 check at boot
5. Hard-exit on cert mismatch when `TAMPER_ENFORCE=true`
6. DeviceIntegrityCheck (root/emu/Frida/debugger probes)
7. Dev-mode hard block (USB-debug enabled = block UI on release)
8. Play Integrity API + server attestation
9. Encrypted session storage (Keystore AES256/GCM)
10. `extractNativeLibs=false` + `allowBackup=false`
11. **r843** InstallSourceVerifier — non-Play installer blocked
12. **r843** ReverseEngineeringDetector — Xposed/LSPosed/Magisk-mgr/Frida/LP scan
13. **r844** `X-Equipseva-Integrity` header on every Supabase request
14. **r845** Periodic 15-min re-verify (catches mid-session compromise)

Plus **r846** server-side persistence of the header into
`device_integrity_checks`, and **r851** edge-fn gate via
`_shared/integrity_gate.ts` (default off via `EDGE_INTEGRITY_ENFORCE`).

To turn full enforcement on in prod:

1. Upload AAB to Play Console → grab Play App Signing SHA-256
2. Add to `EXPECTED_CERT_SHA256` (comma-separated with upload-key SHA)
3. Set `TAMPER_ENFORCE=true` in CI secret
