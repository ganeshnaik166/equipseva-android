## Why this is not full migration replay

The fixture now executes the real defining migrations for three of the nine functions. The other six retain signature-exact stand-ins. Replaying all defining histories is larger than a bounded grant test: `apply_amc_pool_credit` begins in the v2.1 AMC pool migration and is redefined in rounds 474 and 477, which depend on AMC contracts, orders, ledger, jobs, status changes and triggers. The payout functions begin in round424, with webhook/reaper redefinitions in rounds 445 and 466 and picker redefinition in round468; those scripts also create or alter payout/event tables, reconcile data and depend on payout methods, jobs and profiles. The escrow-release function is inside the 628-line v2.1 escrow schema migration, which introduces the escrow/events schema and other participant functions, policies and triggers. The current compact fixture does not model those histories or their full tables. Replaying selected function text while omitting its migration would mislabel the proof as real migration replay.

Round472 is bounded: its telemetry table, RLS policy and RPC run with the fixture's existing roles and `is_founder()` helper. This change therefore increases real-source coverage without weakening the existing legacy failure controls. It does **not** prove the six stand-in bodies, hosted Supabase privileges, provider behavior, production state, or safe deployment.
